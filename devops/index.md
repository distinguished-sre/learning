## Как проходить курс

1. **Иди по порядку.** Уроки выстроены цепочкой: каждый опирается только на пройденное. Внутри темы кнопки «назад» и «дальше» ведут по курсу без пропусков.
2. **Делай практику руками.** В каждом уроке есть шаги с командами и ожидаемым выводом. Не совпало: это повод разобраться, а не пропустить.
3. **Ломай специально.** Задание «сломай и почини» в конце практики учит главному навыку инженера: находить причину, а не симптом.
4. **Проверяй себя вопросами с собеседований.** В каждом уроке от 10 до 20 устных вопросов (обычно 12–14) уровня junior и middle с разбором: что хотят услышать и какой ответ насторожит интервьюера. Плюс тест «Проверь себя» на 30–45 вопросов. Все вопросы собраны на странице [«Подготовка к собеседованию»](interview.md).

**Первый шаг:** [тема 1, урок 1.1](01-linux/index.md). Теорию можно читать с телефона. Практика требует компьютер или облачную ВМ (виртуальную машину в облаке, платную, но у Yandex Cloud есть пробный грант). Нет компьютера: читай теорию, практику отложи.

## Зачем тебе это

После курса ты сможешь работать DevOps-инженером, SRE (инженером по надёжности сервисов) или инженером мониторинга: собрать и выкатить сервис, настроить автоматическую сборку, поднять метрики и алерты, разобрать сбой и написать runbook (инструкцию для дежурного).

## Сквозной проект «Заметки»

Названия инструментов в таблице ниже запоминать не нужно: каждый вводится в своём уроке с объяснением.

Через весь курс идёт один сервис: небольшое HTTP-приложение на Python с эндпоинтами `/healthz`, `/readyz`, `/metrics` и `/notes`, плюс встроенные поломки для тренировки (`/slow`, `/error`, `/leak`, `/burn`). Каждая тема добавляет слой:

| Тема | Что происходит с «Заметками» |
|------|------------------------------|
| 1 | Запускаем на сервере и оформляем systemd-сервисом |
| 2 | Ставим перед сервисом nginx, включаем HTTPS, разбираем путь запроса |
| 3 | Кладём в git, настраиваем CI в GitHub Actions, GitLab CI и Jenkins |
| 4 | Упаковываем в образ, поднимаем с PostgreSQL и nginx в Compose |
| 5 | Запускаем в Kubernetes, обновляем без простоя, упаковываем в Helm |
| 6 | Выносим на ВМ в Yandex Cloud, подключаем Managed PostgreSQL |
| 7 | Описываем инфраструктуру в Terraform, настройку серверов в Ansible |
| 8 | Следим, что сервис жив, и настраиваем оповещения о поломках; разбираем логи и цели по надёжности |
| 9 | Храним пароли безопасно, выкатываем из git автоматически, учимся выпускать новую версию постепенно |
| 10 | Дежурство, постмортем, восстановление из бэкапа, пробное собеседование |

К концу курса у тебя будет репозиторий `notes`, который не стыдно показать на собеседовании: код, CI, Helm-чарт, Terraform, Ansible, дашборды, алерты и runbook.

## Что понадобится

- Компьютер с 16 ГБ RAM. Курс проходится с 8 ГБ (в уроках есть советы, как облегчить стенд), а технические задания для SRE требуют 16 ГБ или облачную ВМ; стеки запускай по очереди.
- Ubuntu 24.04 или Windows с WSL2 (Ubuntu внутри Windows), либо macOS с Docker Desktop или Colima (запуск Docker на macOS без Docker Desktop). Технические задания рассчитаны на Ubuntu 24.04 (локально или на ВМ).
- Аккаунт на GitHub.
- Для тем 6, 7 и 10: аккаунт Yandex Cloud с пробным грантом. В уроках есть таблица соответствия сервисов AWS.

Темп: около 286 часов. По 2 часа каждый день это около пяти месяцев, по 2 часа пять дней в неделю около семи. Технические задания после курса: ещё около 12–16 часов (мониторинг) и около 26–32 часов (SRE). Обычно выходит дольше плана, поэтому оставь запас.
