# CLAUDE.md

Общий стандарт курсов в ../CLAUDE.md, здесь только специфика devops.

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Учебный курс DevOps на русском: Markdown-уроки, которые GitHub Pages (Jekyll 3.10, `baseurl: /learning`, курс на сайте по адресу `/learning/devops/`, сайт собирается из корня репозитория `learning`) собирает в сайт с собственным дизайном в стиле Claude Code (`_layouts/`, `_includes/`, `assets/`). Главный артефакт это сами `.md`. Код в репозитории учебный и служебный: эталонные версии приложения «Заметки» (`project/notes/versions/`, их проверяет `project/notes/check_versions.py`), скрипты поломок к урокам (`project/notes/break/<урок>/break.sh`), аудит уроков `tools/audit.py` (лежит в `tools/` корня репозитория, запуск с `--course devops`) и стенд для проверки уроков `devops/tools/lab/`.

## Структура и навигация

- `_data/courses/devops.yml`: **единственный источник порядка курса**. 10 тем, 82 урока: `topics[].{n, dir, title, subtitle, time, lessons[].{id, slug, title, time}}`. Боковое меню, карта на главной, список уроков темы и кнопки «назад/дальше» (`_includes/nav-seq.html`) строятся из него. Новый урок без записи в devops.yml на сайте недостижим.
- `<NN-тема>/index.md`: страница темы (`layout: topic`), в `redirect_from` старый URL темы.
- `<NN-тема>/<NN-slug>.md`: урок. Front matter: `layout: lesson`, `title`, `topic` (число), `lesson` ("5.3"), `time`. prev/next не пишем, они вычисляются.
- `README.md`: главная (`layout: home`, `permalink: /`), но его текст виден только на GitHub. Сайтовую главную целиком рисует `_layouts/home.html` из `_data/courses/devops.yml` (у тем поля `layer` и `project` для блока «Сквозной проект»); анимации в `assets/css/home.css` и `assets/js/home.js`, `default.html` подключает их только на главной. Меняешь описание тем или цифры курса: правь и README, и devops.yml.
- `tasks/monitoring.md`, `tasks/sre.md`: большие ТЗ после курса; `resources.md`: внешние материалы. У всех `redirect_from` со старых кириллических URL.
- Ссылки только относительные на `.md` (jekyll-relative-links превращает их в `.html`): в своей теме `03-dns.md`, в чужой `../05-kubernetes/03-services-dns.md`. Абсолютные `/01-linux/...` ломаются из-за baseurl.

## Стандарт подачи и перевод курса

Правила курса для новичка, шаблон урока, объяснение понятий, визуал, практика, устные вопросы и тест «Проверь себя» общие для всех курсов: `../CLAUDE.md` и `../tools/theory-style.md`. Шаблон урока devops (прежний, с долей теории 45–55%, схемами только псевдографикой и вопросами внутри `.md`) больше не действует.

Курс переводится на общий стандарт: устные вопросы из уроков переезжают в `_data/questions/devops/open/`, у каждого урока появится банк `_data/questions/devops/quiz/` («Проверь себя»), в урок добавляется раздел «ИИ в помощь». До перевода старые уроки могут ещё быть по старому шаблону: новые и переписанные пиши по общему.

Провал, от которого защищает правило «курс для новичка»: теория занимает четверть урока и написана как справочник (одно-два предложения на понятие, термины через другие термины, без примеров и схем). Ученица о таком уроке сказала: «почти каждый пункт требует дополнительных объяснений», «нихера не объясняется», «для новичка этот курс не подходит». Эталон подачи: [урок 2.1](02-network/01-addresses-routes.md), сверяйся с ним.

Проверки: `python3 tools/audit.py --course devops [урок]` (свои термины урока до «Теории» и термины, которые курс вводит позже; без номера урока доля теории по всем урокам).

## Сквозной проект «Заметки»

`app.py` на stdlib `http.server`, порт 8080, эндпоинты `/healthz`, `/readyz`, `/metrics`, `/notes`; поломки `/slow`, `/error`, `/leak`, `/burn`, `/slowsql`, переменные `READY_FAIL`, `FAIL_RATE`. Репозиторий ученика `~/notes`, на сервере `/opt/notes`, `/var/lib/notes`, `/etc/notes/notes.env`; домен `notes.lab`; kind-кластер и namespace `notes`; образ `ghcr.io/<user>/notes:<semver>`, тег `latest` не используем. Облако Yandex Cloud с таблицей AWS. Современный стек: Gateway API + Envoy Gateway вместо ingress-nginx, Grafana Alloy вместо Promtail, BuildKit вместо Kaniko, `trivy config` вместо tfsec.

При правке урока проверяй, что цепочка не рвётся: имена файлов, порты и пути совпадают с предыдущими уроками.

## Дидактические приёмы, которых нужно придерживаться

- **Задания «сломай и почини».** Почти в каждой теме есть шаг, где ученик намеренно ломает работающую систему (останавливает приложение → 502 в nginx, ставит лимит памяти 8Mi → `OOMKilled`, ломает readiness-пробу → пустые endpoints, катит битую версию → откат Flagger). Это не украшение, а основной способ обучения диагностике: не выкидывай их при рефакторинге.
- **Обратные ссылки на пройденное.** Новая тема явно опирается на предыдущие: коды 502/504 из темы 2 всплывают в темах 4 и 5, `SIGTERM` из темы 1 возвращается в Docker и Kubernetes, DNS по имени сервиса встречается в Compose и затем в кластере.
- **Разбор ошибок.** В `**Типичные ошибки:**` пишут реальную формулировку ошибки (`ImagePullBackOff`, `bad interpreter`, `port is already allocated`) и причину, а не общие советы.

## Стиль текста

- Русский язык, обращение к ученику на «ты», аудитория: новичок без опыта в IT. Термины поясняются при первом появлении (`../CLAUDE.md`, «Как объяснять понятие»), английский оригинал в скобках: наблюдаемость (observability).
- Комментарии в коде и конфигах пишутся на русском и объясняют, зачем строка нужна. Они часть учебного материала, не сокращай их при рефакторинге примеров.
- Версии инструментов указываются явно и закрепляются, текст ссылается на актуальный год. Какая версия принята сейчас, смотри в уроках (`git grep -h 'postgres:'`), а не в этом файле. При обновлении содержимого проверяй согласованность версий и датировок по всему курсу.
- Проверяй команды в примерах на актуальность, прежде чем оставлять их. Типичные устаревшие: `actions/checkout@v2`, `kubectl run --generator=run-pod/v1` (удалён в k8s 1.18), `version: '3.8'` в Compose.
