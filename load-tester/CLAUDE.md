# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Два продукта на одном GitHub Pages (https://distinguished-sre.github.io/load-tester/, Jekyll 3.10, `baseurl: /load-tester`):

1. **Лендинг-гайд** `index.html` в корне: «Путь в автоматизацию и нагрузочное тестирование с нуля». Статический файл без front matter, Jekyll копирует его как есть. Устройство и правила ниже в разделе «Лендинг».
2. **Курс** нагрузочного тестирования и мониторинга для новичка: Markdown-уроки, которые Jekyll собирает в сайт (`/course/` главная курса, `_layouts/`, `_includes/`, `assets/`). Дизайн и механика взяты из соседнего курса DevOps (github.com/distinguished-sre/devops) и адаптированы.

Курс общий, для любого новичка. Никаких имён конкретных учеников, работодателей и историй «для кого написан» в текстах, коммитах и примерах.

## Команды

```bash
# лендинг без сборки
python3 -m http.server 8777 --bind 127.0.0.1        # http://127.0.0.1:8777/index.html
# аудит уроков: доля теории и термины до объяснения
python3 tools/audit.py [урок]

cd project/shop && cp .env.example .env && docker compose --profile monitoring up -d --build --wait
```

Деплой: `.github/workflows/deploy.yml` собирает Jekyll и публикует при push в `main`. `stand.yml` поднимает стенд на ubuntu-latest и гоняет эталонные тесты из `project/shop/examples/` при изменениях в `project/shop/`.

## Главное правило: курс для новичка

Читатель не работал в IT, умеет пользоваться компьютером. Урок сам отвечает хотя бы на 90% вопросов, которые возникнут по ходу чтения, без поиска в интернете. Если после абзаца хочется спросить «а что это?» или «а почему так?», абзац не готов. Ученик лучше всего понимает **визуальное**: схемы, анимации, графики. Текст объясняет картинку, картинка показывает механизм.

## Шаблон урока

1. `## Зачем это нужно`: какую рабочую задачу решает тема, и абзац «Шаг проекта».
2. `## Что нужно знать`: ссылки на предыдущие уроки и что из них понадобится.
3. `## Картина целиком`: до 300 слов, аналогия из жизни и **схема** (mermaid или виджет), как части темы связаны.
4. `## Теория`: главная часть, 40–50% объёма (обычно 1800–3000 слов; урок рассчитан на 1–2 занятия по 1,5–2 часа). Разделы `###` по одному понятию.
5. `## Практика`: задания с командами, ожидаемым выводом и разбором.
6. `## Сломай и почини`: намеренная поломка и диагностика.
7. `## Словарик урока`: таблица «термин | простыми словами».
8. `## Вопросы с собеседований`: 8–12 штук.
9. `## Проверено на версиях` и `## Итог урока: ты умеешь` (чек-лист), затем ссылка «Дальше».

### Как объяснять понятие

Пять шагов, пропускать только очевидные: **зачем существует** (что было бы без него), **аналогия** (одна, с оговоркой, где ломается), **как устроено** (по шагам, в реальном порядке), **разобранный пример** (реальные значения или вывод, каждое поле объяснено, вычисления целиком), **что путают**. Затем `> **Проверь понимание:**` с ответом в `<details>`.

- **Термин объясняется там, где впервые встретился**, в том же абзаце: 2–4 предложения простыми словами, пример из жизни, зачем нужен. Термин из прошлых уроков: фраза-напоминание и ссылка. Английский оригинал в скобках. Нельзя объяснять термин через необъяснённый термин.
- Ничего не предполагать о знаниях, которых курс ещё не дал.
- Факты не списком «X это Y», а с причинами и следствиями.
- Короткие абзацы, живой тон на «ты». Без канцелярита и без длинного тире: вместо него двоеточие, запятая, скобки или « - ». Кавычки «ёлочки», буква «ё».

### Визуал: обязательно

В каждом уроке **не меньше трёх** визуальных элементов, из них минимум одна схема mermaid или виджет. Картинка ставится рядом с текстом, который она объясняет, и после неё 1–3 предложения «что здесь видно».

- **Mermaid** (```` ```mermaid ````): `flowchart` для путей запроса, устройства системы, алгоритмов диагностики («если… то…»); `sequenceDiagram` для обмена сообщениями (HTTP, логин с токеном, скрейп Prometheus); `stateDiagram-v2` для состояний; `xychart-beta` и `pie` для простых данных. Подписи по-русски, узлы короткие. site.js грузит mermaid только на страницах с такими блоками.
- **Виджеты** `assets/js/viz.js`, разметка `<div class="viz" data-viz="ИМЯ" ...></div>` (живой пример всех: `viz-demo.md`, `/viz-demo.html`):
  - Все виджеты стартуют сами со значений из атрибутов, когда видны на экране; есть «Пауза», при «уменьшить движение» статичный кадр. Под виджетом сам виджет пишет блок «Что сейчас происходит» и строку «Попробуй: …». В уроке после виджета 1–3 предложения, на что смотреть, без пересказа этого блока и без слова «Пуск».
  - `request-path` (data-net, data-app, data-db в мс): анимация пути запроса и ответа;
  - `queue` (data-servers, data-rate покупателей в минуту, data-service секунд на одного): очередь и насыщение;
  - `percentiles` (data-slow из 100, data-slow-ms; `latency-hist` работает как алиас): среднее против p50/p95/p99;
  - `hockey-stick` (data-capacity, data-base, data-load, data-unit): нагрузка против задержки, запас до предела;
  - `load-profiles` (data-only): формы smoke/load/stress/soak/spike;
  - `pool` (data-size, data-duration, data-rate, data-timeout): пул соединений, ожидание и таймауты;
  - `chart` (data-type, data-x, data-series с `"unit"` у серии, data-x-label, data-y-label, data-unit, data-explain): график по данным, подсказка при наведении, легенда кликабельна;
  - `flow` (data-steps: строки или `{"title": "до 6 слов", "text": "подробности"}`, обратные кавычки дают `<code>`): пошаговая блок-схема: все шаги видны сразу, сверху вниз, при первом показе выстраиваются по очереди.
  - Объяснения в виджетах: без формул, простыми словами и с примерами.
- **Mermaid-схема**: по умолчанию `flowchart TD`, не больше 4 узлов в ряд, подписи до ~25 символов в строке (перенос `<br>`), без глубокой вложенности subgraph. Широкая схема ужимается не больше чем до 0,8, дальше прокручивается: лучше разбить на две.
- **Псевдографика** ```` ```text ```` годится для раскладки файлов и вывода команд, но не заменяет схему.
- Результаты тестов показывай графиком (`chart`) с реалистичными числами, а не только таблицей.
- Виджеты одной темы можно класть в `assets/js/viz/<папка-темы>.js`: такие файлы подключаются автоматически и регистрируют виджеты через `window.LTViz` (API в конце `viz.js`), свои стили добавляют одним `<style>` на CSS-переменных сайта.
- Новый виджет добавляй в `viz.js` (через `setup()`/`animate()`, обязательно `v.explain()`, `v.tryIt()` и подсказки через `v.hover()` + `v.showTip()`: как в Grafana, в любой точке графика, а не только над линией) и в `viz-demo.md`, а не инлайн-скриптом в уроке.

### Как подавать практику

- Перед новой командой: что делает, разбор каждой части (флаги, аргументы, `|`, `$(...)`). Повторную команду: напоминание в одну строку.
- После ожидаемого вывода `**Как читать вывод:**`: что значит каждая строка или колонка, на что смотреть первым.
- `**Типичные ошибки:**` с реальным текстом ошибки, причиной и исправлением.
- Не предполагать окружение, которое курс не настроил.

### Вопросы с собеседований

Раздел начинается строкой «Раздел для повторения: ответь вслух, потом открой ответ». Формат `### N. [junior|middle] Вопрос`; первые 2–3 самые частые помечены `[junior] [часто]`. Далее `<details markdown="1">` с `<summary>Ответ</summary>`, ответ, `**Что хотят услышать:**`, `**Красный флаг:**`. Ответы опираются только на пройденное. Учимся отвечать вслух и на время: часть вопросов в каждой теме короткие «на скорость» (базовые факты, которые на собеседовании забывают от волнения). Исключение: 13.4 и 13.5 (пробные собеседования) держат банки по 30–40 вопросов для тренировки.

Ученик не пишет сервис, он его тестирует, как тестировщик на работе. Свои тесты, сценарии, дашборды и отчёты ученик складывает в собственный репозиторий `~/perf-lab` (заводится в теме 3), стенд берёт из клона этого репозитория: `~/load-tester/project/shop`.

Пользователи `user0001@shop.lab`…`user1000@shop.lab`, пароль `password`; 10 000 товаров, 200 000 исторических заказов.
- `payment`: заглушка оплаты, порт 8001, `/pay`, `/admin/config` (задержка и доля ошибок на лету).
- PostgreSQL 5432 (`shop/shop/shop`, pg_stat_statements), Redis 6379. Профиль `monitoring`: Prometheus 9090, Alertmanager 9093, Grafana 3000, Loki 3100, Tempo 3200, Alloy 12345 (OTLP/HTTP 4318 внутри сети), node-exporter, cAdvisor, postgres-exporter.
- Метрики: `http_requests_total{method,route,status}`, `http_request_duration_seconds`, `http_requests_in_progress`, `shop_db_pool_{size,available,waiting}`, `shop_db_connection_wait_seconds`, `shop_cache_requests_total{result}`, `shop_orders_created_total`, `shop_payment_requests_total{result}`, `shop_payment_duration_seconds`. Логи JSON со `request_id` и `trace_id` (рядом, в таком порядке). Трейсы OpenTelemetry (SDK + автоинструментация FastAPI, httpx, psycopg, Redis; `traceparent` shop → payment, спан `db.pool.getconn`) идут OTLP/HTTP → Alloy → Tempo; в Grafana источник Tempo, из лога Loki переход по `trace_id` в трейс и обратно; `TRACING_ENABLED`, `OTEL_*`. Всем долгоживущим сервисам `restart: unless-stopped`.
- Заложенные узкие места (переменные в `.env`, список с починкой в `project/shop/README.md`): bcrypt-логин и один воркер (`BCRYPT_ROUNDS`, `WEB_CONCURRENCY`, урок 11.2), нет индекса `orders.user_id` и N+1 (`BUG_N_PLUS_ONE`, 11.3), маленький пул (`DB_POOL_MAX`, 11.3), утечка (`LEAK_ENABLED`, 11.4), кэш (`CACHE_ENABLED`) и оплата внутри транзакции с ретраями без паузы (`PAYMENT_TIMEOUT`, `PAYMENT_RETRIES`, 11.5).
- Нагрузку даём только на свой локальный стенд. В уроках прямо сказано, что нагружать чужие сайты нельзя.

При правке урока проверяй, что цепочка не рвётся: порты, пути, имена метрик и файлов совпадают с `project/shop` и предыдущими уроками. Меняешь проект: обнови README проекта, этот раздел и затронутые уроки.

## Jekyll и двойные фигурные скобки

Liquid обрабатывает все `.md` до Markdown: `{{ ... }}` и `{% ... %}` в тексте либо роняют сборку, либо молча исчезают (шаблоны Grafana и Alertmanager, Jinja). Всё, что их содержит, оборачивается в `{% raw %}` / `{% endraw %}`: для блока кода снаружи ограждения, для inline-кода вокруг обратных кавычек. `CLAUDE.md` и `README.md` в `exclude`. Проверка перед коммитом (последним действием):

```bash
gem install --user-install --no-document liquid -v 4.0.4
ruby -e '$LOAD_PATH.unshift(File.expand_path("~/.gem/ruby/2.6.0/gems/liquid-4.0.4/lib"))
require "liquid"; require "yaml"
skip = YAML.load_file("_config.yml")["exclude"] || []
(Dir.glob("**/*.md") - skip - Dir.glob("_site/**/*") - Dir.glob("project/**/*")).each { |f| begin
  src = File.read(f); out = Liquid::Template.parse(src).render
  kept = src.gsub(/\{%-?\s*raw\s*-?%\}(.*?)\{%-?\s*endraw\s*-?%\}/m) { $1 }
  ["{{", "{%"].each { |t| d = kept.scan(t).size - out.scan(t).size; puts "#{f}: после render пропало #{d} шт. #{t}" if d != 0 }
rescue => e; puts "#{f}: #{e.message}"; end }'
```

## Лендинг (`index.html`)

Порядок в файле: `<head>` с мета-тегами и inline-скриптом анимации → `<style>` → `<main>` с семью `<section>` → три `<script>` в конце.

- **Блокирующий скрипт в `<head>`** вешает `anim` на `<html>` и через IntersectionObserver добавляет `in` на `.hero`, `section`, `.track`; отключается при `prefers-reduced-motion` и на ширине ≤700px. `try/catch`-фолбэк показывает всё: не ломай его.
- **Стили** на CSS-переменных в `:root`, тёмная тема через `@media (prefers-color-scheme: dark)`, светлое и тёмное значение правятся парой. Фон `body::before` (`bg.jpg`) и вуаль `body::after` (`--veil`).
- **Двуязычность**: `data-en` (RU снимается из `textContent`), `data-en-aria`; словарь `EN_HTML` для блоков со ссылками (блок обязан иметь `id` = ключ); `EN_PROMPT` для промпта. **Правки промпта всегда парные: RU в `<pre id="prompt">` и EN в `EN_PROMPT`**, `grep -c '\${' index.html` должно быть 0. Язык в `localStorage` под `lang`.
- **Третий скрипт**: копирование промпта, `#progress`, `#jump`, подсветка `.stop`, делегированный обработчик `a[href="#start"]` (ссылки в переводимых блоках пересоздаются).
- `#osHint` по `navigator.platform`, тексты в `OS_HINT`.
- Без внешних зависимостей, кроме Google Fonts; диаграммы inline-SVG; вес `index.html` около 100 КБ; `og.jpg` ровно 1200×630. Заголовок и описание правятся в четырёх местах: `<title>`, `meta[name=description]`, og-теги, `titleEn`/`metaEn`.
