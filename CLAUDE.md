# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Общий стандарт курсов сайта: подача, шаблон урока, тест «Проверь себя», устные вопросы, визуал, Jekyll, работа агентами. Специфика курса (структура, сквозной проект, версии, свои команды) в `<курс>/CLAUDE.md`. Эталон стандарта: курс load-tester, примеры из него помечены.

## Что это

Сайт «Обучение» на GitHub Pages: https://distinguished-sre.github.io/learning/ (репозиторий github.com/distinguished-sre/learning, Jekyll 3.10, `baseurl: /learning`, сайт собирается из корня). Три курса: `devops/`, `load-tester/`, `monitoring/` (готовится). Общее лежит в корне: `_config.yml`, `_layouts/`, `_includes/`, `assets/`, `_data/courses/<курс>.yml` (порядок курса), `_data/questions/<курс>/{quiz,open}/MM-LL.json` (банки вопросов), `tools/` (скрипты проверки с `--course`, `theory-style.md`, `readers.md`), `.github/workflows/`. Главную сайта (хаб) рисует `_layouts/hub.html`.

Ключи `localStorage` (один origin на все курсы), **не менять: потеряется прогресс учеников**:
- прохождение уроков: devops `done`, load-tester `lt:done`, monitoring `mon:done`;
- тесты «Проверь себя»: `dv-quiz:v1:<урок>`, `lt-quiz:v1:<урок>`, `mon-quiz:v1:<урок>`;
- `theme`: общий для всех курсов.

Курсы общие, для любого новичка: никаких имён конкретных учеников, работодателей и историй «для кого написан» в текстах, коммитах и примерах.

## Команды

Скрипты лежат в `tools/`, запускай из корня репозитория. `--course devops|load-tester|monitoring`: без него `audit.py`, `readability.py` и `check_snippets.py` берут все курсы, у которых есть `_data/courses/<курс>.yml`, а `check_questions.py` по умолчанию load-tester.

```bash
# сборка как на Pages (Jekyll 3.10, gem github-pages), результат в _site/
bundle exec jekyll build
# аудит уроков: доля теории и термины до объяснения
python3 tools/audit.py [--course <курс>] [--json] [урок]
# читаемость теории; --terms: термины словариков до урока (нужен один курс)
python3 tools/readability.py [--course <курс>] [--json] [--terms] [урок]
# синтаксис блоков кода в уроках (bash -n, py_compile, node --check; CI snippets.yml)
python3 tools/check_snippets.py [--course <курс>]
# база вопросов: структура, покрытие, дубли; --site: собранный сайт (банк в уроке, якоря, JSON тем, ссылки)
python3 tools/check_questions.py --course <курс> [--stats] [--only 05-03,05-04] [--site _site]
# логика тестов без DOM (банки курса COURSE, по умолчанию load-tester)
COURSE=<курс> node --test tools/quiz.test.mjs
# тесты в настоящем браузере по собранному сайту: две вкладки, битая запись, фокус (в CI quiz.yml)
npm install --no-save playwright && npx playwright install chromium && COURSE=<курс> SITE_DIR=_site node --test tools/browser.test.mjs
```

Деплой: `.github/workflows/deploy.yml` собирает Jekyll и публикует при push в `main`. `quiz.yml` проверяет банки вопросов и логику тестов, собирает сайт, как Pages, и сверяет собранные страницы; сейчас гоняет только load-tester (`--course load-tester`, `COURSE=load-tester`), новый курс добавляй в эти шаги. `snippets.yml`: синтаксис кода, сейчас только load-tester (devops выключен: 17 ошибок в плейсхолдерах). `stand.yml`: стенд load-tester (см. `load-tester/CLAUDE.md`).

## Главное правило: курс для новичка

Читатель не работал в IT, умеет пользоваться компьютером. Урок сам отвечает хотя бы на 90% вопросов, которые возникнут по ходу чтения, без поиска в интернете. Если после абзаца хочется спросить «а что это?» или «а почему так?», абзац не готов. Ученик лучше всего понимает **визуальное**: схемы, анимации, графики. Текст объясняет картинку, картинка показывает механизм.

## Шаблон урока

1. `## Зачем это нужно`: какую рабочую задачу решает тема, и абзац «Шаг проекта».
2. `## Что нужно знать`: ссылки на предыдущие уроки и что из них понадобится.
3. `## Картина целиком`: до 300 слов, аналогия из жизни и **схема** (mermaid или виджет), как части темы связаны.
4. `## Теория`: главная часть (вместе с «Зачем это нужно» и «Картиной целиком» обычно 1500–2500 слов; урок рассчитан на 1–2 занятия по 1,5–2 часа). Разделы `###` по одному понятию.
5. `## Практика`: задания с командами, ожидаемым выводом и разбором.
6. `## Сломай и почини`: намеренная поломка и диагностика.
7. `## ИИ в помощь`: 2–4 рабочих сценария темы: `**Задача:**`, готовый запрос в ```` ```text ```` со строкой `{: .wrap}` после блока, `**Проверь ответ:**` (что сверить и типичная ошибка нейросетей в теме). Ссылка на страницу «ИИ-помощник» курса (`ai.md`, пример из load-tester: `../ai.md`), общие правила не повторять. По ходу практики 1–2 пометки цитатой с `{: .ai}` на следующей строке.
8. `## Словарик урока`: таблица «термин | простыми словами».
9. `## Вопросы с собеседований`: вводный абзац и `{% include interview.html %}`, сами вопросы (8–12) в `_data/questions/<курс>/open/`.
10. `## Проверено на версиях` и `## Итог урока: ты умеешь` (чек-лист), затем ссылка «Дальше». Тест «Проверь себя» (банк `quiz`) выводит `_layouts/lesson.html` и ставит его перед «Дальше».

### Как объяснять понятие

Подробно, с примерами разметки: `tools/theory-style.md` (для «Зачем это нужно», «Картины целиком» и «Теории»). Коротко: пишет наставник от первого лица («я», без имени), с типовыми байками без брендов и имён; сквозной сюжет курса (ситуации по темам) описан в `CLAUDE.md` курса. Раздел `###` идёт рассказом без жирных ярлыков: крючок → явление на житейском примере, потом название → как устроено → пример на сквозном проекте курса с числами → `> **Прикинь сам:**` (`{: .predict}`) → «Осторожно» (что путают) → `> **Главное:**` (`{: .key}`) → мостик к следующему разделу. Формулы: пример, правило словами, потом формула. `> **Проверь понимание:**` раз в 1–2 раздела. Подробности, нужные практике и собеседованию, в `<details>` «Для любопытных» (до двух на урок). Метрики: `python3 tools/readability.py --course <курс> [урок]`. Аудит тремя новичками (портреты в `tools/readers.md`): урок проходит, если понятность не ниже 4 у всех троих, интерес не ниже 4 хотя бы у двух, пересказ верен и нет необъяснённых слов.

- **Термин объясняется там, где впервые встретился**, в том же абзаце: 2–4 предложения простыми словами, пример из жизни, зачем нужен. Термин из прошлых уроков: фраза-напоминание и ссылка. Английский оригинал в скобках один раз, если слово встретится в интерфейсе, коде, выводе команды или на собеседовании. Нельзя объяснять термин через необъяснённый термин.
  - Первая встреча в курсе: что это, пример из жизни, зачем нужно и какую ценность даёт (что было бы без него). Пример объёма (формулировку и аналогию подбирай свои, схему «X - это Y, как Z» не копируй; пример из devops): «Шлюз (gateway) - это выход из твоей сети наружу, как проходная на заводе: всё, что едет за территорию, идёт через неё. Без шлюза машина видит только соседей по своей сети, а интернет для неё не существует».
  - Термин, который курс разберёт подробно позже: те же 2–4 предложения с примером и ссылка вперёд («подробно разберём ниже»).
  - Где бы термин ни встретился («Зачем это нужно», «Картина целиком», практика, вопрос собеседования), читатель не должен дочитывать до объяснения с вопросом «а что это?».
- Ничего не предполагать о знаниях, которых курс ещё не дал (двоичная система, что такое пакет, процесс, файл конфигурации, переменная окружения): нужное для урока объясняется прямо в уроке.
- Факты не списком «X это Y», а с причинами и следствиями.
- Короткие абзацы, живой тон на «ты». Без канцелярита и без длинного тире: вместо него двоеточие, запятая, скобки или « - ». Кавычки «ёлочки», буква «ё».
- Кандидатов на «термин до объяснения» и долю теории по урокам даёт `python3 tools/audit.py --course <курс> [урок]`: список грубый (основа слова, есть ложные срабатывания), решение по месту за автором.

### Визуал: обязательно

В каждом уроке **не меньше трёх** визуальных элементов, из них минимум одна схема mermaid или виджет. Картинка ставится рядом с текстом, который она объясняет, и после неё 1–3 предложения «что здесь видно».

- **Mermaid** (```` ```mermaid ````): `flowchart` для путей запроса, устройства системы, алгоритмов диагностики («если… то…»); `sequenceDiagram` для обмена сообщениями (HTTP, логин с токеном, скрейп Prometheus); `stateDiagram-v2` для состояний; `xychart-beta` и `pie` для простых данных. Подписи по-русски, узлы короткие. site.js грузит mermaid только на страницах с такими блоками.
- **Виджеты** `assets/js/viz.js`, разметка `<div class="viz" data-viz="ИМЯ" ...></div>` (живой пример всех: `load-tester/viz-demo.md`, `/learning/load-tester/viz-demo.html`):
  - Все виджеты стартуют сами со значений из атрибутов, когда видны на экране; есть «Пауза», при «уменьшить движение» статичный кадр. Под виджетом сам виджет пишет блок «Что сейчас происходит» и строку «Попробуй: …». В уроке после виджета 1–3 предложения, на что смотреть, без пересказа этого блока и без слова «Пуск».
  - `request-path` (data-net, data-app, data-db в мс): анимация пути запроса и ответа;
  - `queue` (data-servers, data-rate покупателей в минуту, data-service секунд на одного): очередь и насыщение;
  - `percentiles` (data-slow из 100, data-slow-ms; `latency-hist` работает как алиас): среднее против p50/p95/p99;
  - `hockey-stick` (data-capacity, data-base, data-load, data-unit): нагрузка против задержки, запас до предела;
  - `load-profiles` (data-only): формы smoke/load/stress/soak/spike;
  - `pool` (data-size, data-duration, data-rate, data-timeout): пул соединений, ожидание и таймауты;
  - `chart` (data-type, data-x, data-series с `"unit"` у серии, data-x-label, data-y-label, data-unit, data-explain): график по данным, подсказка при наведении, легенда кликабельна;
  - `flow` (data-steps: строки или `{"title": "до 6 слов", "text": "подробности"}`, обратные кавычки дают `<code>`): пошаговая блок-схема: все шаги видны сразу, сверху вниз, при первом показе выстраиваются по очереди.
  - Объяснения в виджетах: без формул, простыми словами и с примерами.
- **Mermaid-схема**: по умолчанию `flowchart TD`, не больше 4 узлов в ряд, подписи до ~25 символов в строке (перенос `<br>`), без глубокой вложенности subgraph. Широкая схема ужимается не больше чем до 0,8, дальше прокручивается: лучше разбить на две.
- **Псевдографика** ```` ```text ```` годится для раскладки файлов и вывода команд, но не заменяет схему.
- Результаты тестов показывай графиком (`chart`) с реалистичными числами, а не только таблицей.
- Виджеты одной темы можно класть в `assets/js/viz/<папка-темы>.js` (у monitoring с префиксом `monitoring-<папка-темы>.js`, чтобы имена не пересеклись): такие файлы подключаются автоматически и регистрируют виджеты через `window.LTViz` (API в конце `viz.js`), свои стили добавляют одним `<style>` на CSS-переменных сайта.
- Новый виджет добавляй в `viz.js` (через `setup()`/`animate()`, обязательно `v.explain()`, `v.tryIt()` и подсказки через `v.hover()` + `v.showTip()`: как в Grafana, в любой точке графика, а не только над линией) и в `load-tester/viz-demo.md`, а не инлайн-скриптом в уроке.

### Как подавать практику

- Перед новой командой: что делает, разбор каждой части (флаги, аргументы, `|`, `$(...)`). Повторную команду: напоминание в одну строку.
- После ожидаемого вывода `**Как читать вывод:**`: что значит каждая строка или колонка, на что смотреть первым.
- `**Типичные ошибки:**` с реальным текстом ошибки, причиной и исправлением.
- Не предполагать окружение, которое курс не настроил: всё, что ставится или создаётся, ставится и создаётся в уроке или по ссылке на урок.

### Вопросы с собеседований

Раздел начинается строкой «Раздел для повторения: ответь вслух, потом открой ответ», вопросы лежат в `_data/questions/<курс>/open/NN-MM.json`, include выводит их как `### N. [junior|middle] Вопрос` с `<details markdown="1">`. Первые 2–3 самые частые с тегами `junior` и `часто`. Ответ содержит `**Что хотят услышать:**` и `**Красный флаг:**`. Ответы опираются только на пройденное, новый термин в ответе объясняется там же. Учимся отвечать вслух и на время: часть вопросов в каждой теме короткие «на скорость» (базовые факты, которые на собеседовании забывают от волнения). Банки пробных собеседований, если они есть в курсе, могут быть по 30–40 вопросов (пример из load-tester: 13.4 и 13.5).

### Единая база вопросов `_data/questions/<курс>/`

Одна база для уроков, страницы подготовки и пробных собеседований, без копий в тексте уроков. Проверка: `python3 tools/check_questions.py --course <курс>`.

- `open/NN-MM.json`: устные вопросы с собеседований: `{lesson, topic, questions:[{id: "oNN-MM-KK", n, tags, q, answer, group?}], groups?}`. Теги из `junior`, `middle`, `часто`, `на скорость`; `answer` в Markdown со ссылками на `.md`; `groups` только где курс их использует (пример из load-tester: 13.4 и 13.5). В уроке раздел выводит `{% include interview.html %}`.
- `quiz/NN-MM.json`: тест «Проверь себя»: `{lesson, topic, block, questions:[{id: "qNN-MM-KK", skill, kind, type, text, code?, options:[{id: "a".."f", text, why?}], correct, explain, section}]}`. 25–50 вопросов, `block` 5 или 10 и делит банк без остатка. `kind`: понимание, применение, чтение, диагностика. `type`: `single` (ровно один верный) или `multiple` (два и больше, но не все). `why` обязательно у неверных вариантов, `section` точный текст заголовка `##`/`###` урока (по нему строится ссылка на раздел). В текстах разметка только `` `код` ``.
- Блок теста выводит `_layouts/lesson.html` (`_includes/quiz.html`), скрипт ставит его перед «Дальше». Логика без DOM в `assets/js/quiz-core.js` (порог 60% включительно, multiple только точное совпадение, без повторов до исчерпания банка), карточки в `quiz-ui.js`, урок в `quiz.js`: предупреждение перед следующим уроком никогда не блокирует переход.
- ID вопросов и вариантов стабильные: не перенумеровывать, удалённый ID не переиспользовать. Переименовал заголовок урока: поправь `section` (валидатор найдёт).

## Jekyll и двойные фигурные скобки

Liquid обрабатывает все `.md` до Markdown: `{{ ... }}` и `{% ... %}` в тексте либо роняют сборку, либо молча исчезают (шаблоны Grafana и Alertmanager, Jinja). Последствия двух видов, второй хуже:
- сборка падает с `Liquid syntax error` (так уронила Pages конструкция `f'...{{status="{status}"}}...'` в примере на Python);
- сборка проходит, но содержимое молча подставляется пустым: Helm-шаблоны (`{{ .Values.image.tag }}`), переменные Ansible/Jinja2 (`{{ ansible_hostname }}`), аннотации Prometheus (`{{ $labels.instance }}`) исчезают со страниц, хотя в репозитории выглядят правильно.

Правило: всё, что содержит `{{` или `{%`, оборачивается в `{% raw %}` / `{% endraw %}`: для блока кода снаружи ограждения (с тем же отступом, что у ```` ``` ````), для inline-кода вокруг обратных кавычек. `CLAUDE.md`, `README.md` и `tools/` в `exclude` (`_config.yml`). `CLAUDE.md` приводит Liquid-теги как текст и уронил бы сборку. Указав свой `exclude`, мы заменяем стандартный список Jekyll целиком, поэтому в нём перечислены и обычные служебные пути. Проверка перед коммитом (последним действием):

```bash
gem install --user-install --no-document liquid -v 4.0.4
ruby -e '$LOAD_PATH.unshift(File.expand_path("~/.gem/ruby/2.6.0/gems/liquid-4.0.4/lib"))
require "liquid"; require "yaml"
skip = YAML.load_file("_config.yml")["exclude"] || []
(Dir.glob("**/*.md") - skip - Dir.glob("_site/**/*") - Dir.glob("**/project/**/*")).each { |f| begin
  src = File.read(f); out = Liquid::Template.parse(src).render
  kept = src.gsub(/\{%-?\s*raw\s*-?%\}(.*?)\{%-?\s*endraw\s*-?%\}/m) { $1 }
  ["{{", "{%"].each { |t| d = kept.scan(t).size - out.scan(t).size; puts "#{f}: после render пропало #{d} шт. #{t}" if d != 0 }
rescue => e; puts "#{f}: #{e.message}"; end }'
```

## Работа агентами

Параллельные субагенты здесь дороже всего: каждый заново читает этот файл, `CLAUDE.md` курса, `tools/theory-style.md` и уроки. 03.10 три сессии раздали от 30 до 220 агентов и за день съели около 28% недельного лимита Claude.

- Одновременно не больше 4 агентов, за сессию не больше 15. Нужно больше: сначала спроси пользователя, назови число агентов и что получится в итоге.
- Пачка: тема целиком, а не урок или группа вопросов. Один агент пишет или правит все уроки темы.
- Серию однотипных задач начинай с одного агента. Проверь результат, потом раздавай остальное с той же постановкой.
- Кому отдавать:
  - написать или переписать урок, внести правки по ревью → `worker`;
  - проверить без правок (факты, банк вопросов по правилам выше, ссылки, порты и имена по цепочке уроков) → `scout`, ответ списком замечаний; правки потом одним `worker` на тему;
  - аудит тремя новичками из `tools/readers.md` → `reader`, один агент на персону и тему, не на урок;
  - механика (JSON вопросов, массовые замены, переименования) → `cxw task`, при коде 75 → `worker`.
- `general-purpose` не вызывай.
- Скрипты проверки (`tools/audit.py`, `tools/readability.py`, `tools/check_questions.py`) запускай сам, агент для них не нужен.
- `scout` и `reader` CLAUDE.md не видят: правила, которые нужны для проверки, вставляй в постановку текстом, вместе с путями к файлам.

## Новый курс

1. Папка `<курс>/`: `index.md` (главная курса), `<NN-тема>/index.md` (`layout: topic`), уроки `<NN-тема>/<NN-slug>.md` (`layout: lesson`, `title`, `topic`, `lesson`, `time`).
2. `_data/courses/<курс>.yml`: порядок курса (`topics[].{n, dir, title, subtitle, time, layer, project, lessons[].{id, slug, title, time}}`), время темы равно сумме уроков. Курс добавь в `COURSES` в `tools/courses.py` и в `choices` в `tools/check_questions.py`.
3. `_config.yml`, `defaults`: scope `<курс>` со значениями `course: <курс>` и `image`, scope на каждую папку темы со `layout: lesson`.
4. Ключи `localStorage`: префикс прохождения в `PREFIX` в `assets/js/site.js` (итоговый ключ `<префикс>:done`), префикс тестов в `QUIZ_PREFIX` в `assets/js/quiz-core.js` (ключ `<префикс>-quiz:v1:<урок>`). Занятые ключи не менять.
5. Карточка курса на хабе `_layouts/hub.html` (цифры из `_data/courses/<курс>.yml`), строка в `README.md`.
6. Банки `_data/questions/<курс>/{quiz,open}/` и шаги CI (`quiz.yml`, `snippets.yml`) для нового курса.
7. `<курс>/CLAUDE.md`: первой строкой «Общий стандарт курсов в ../CLAUDE.md, здесь только специфика <курса>», дальше структура, сквозной проект, версии, свои команды.
